Authoring Tool Accessibility Guidelines - Use Cases and Requirements

The goal of this document and exercise is to gather use cases, user stories, and requirements for authoring tools present and future.

Introduction

User Types

There are many users that use authoring tools for a variety of tasks and functions. Almost every task or job role contains an element of authoring. To focus our efforts, we have grouped users into three main roles:

  • Creator: the originator of the content or tool, responsible for the creation of the end product and its foundational accessibility.
  • Maintainer: the user of existing product or content who modifies or maintains it.
  • Consumer: the end user of the product or content who engages with it as it is.

Authoring Tool Functions

Authoring tools perform a number of different functions. Each of the following functions exist on a spectrum ranging from the most basic to the most advanced. For example, a rich text editing interface can range from a simple textbox that offers the ability to bold or underline text, to a complex document editing interface that offers advanced typesetting features.

We have identified the following authoring tool functions:

  • Rich text editing interface
  • Audio editing interface
  • Video editing interface
  • Image editing interface
  • Diagram editing interface
  • Voice editing interface
  • Programming interface
  • VR, XR, 3D CAD editing interface
  • Collaborative editing tools
  • Version control interface
  • Annotations and comments
  • Content templates
  • Generative AI or LLM interfaces
  • Content previews
  • Content translation

Use Cases for Authoring Tools

The use cases for authoring tools are structured by the actions taken during authoring processes. The authoring process is not linear, and the actions taken depend highly on the content being produced, the intent of the user, and the needs of the end user.

Content creation

The following use cases are focused on the creation of new content using an authoring tool.

Creating media content

Users must be able to author accessible content in different media types using the necessary accessibility features or alternatives.

Users may achieve this for:

  1. Textual content, by including all semantics necessary for content structure and formatting.
  2. Audio content, by including textual alternatives such as transcripts and descriptions.
  3. Video content, by including textual alternatives such as captions, transcripts, and descriptions.
  4. Image content, by including textual alternatives such as alternative text and extended descriptions.
  5. Complex visual content, such as charts, graphs, and visualizatons, by including alternative text, text summaries, extended descriptions, or audio alternatives.

Creating technical content

Users must be able to author accessible technical content such as software or source files for complex content using the necessary accessibility features.

Users may achieve this for:

  1. Markup languages, such as HTML, XML, MarkDown, or LaTeX, by using the language's accessibility features, validation tools, and authoring tools that support accessible development.
  2. Programming languages, such as Java, Javascript, C, or C#, by using the language's accessibility features, validation tools, and authoring tools that support accessible development.
  3. Computer-aided design (CAD) files, [TODO: Does CAD have accessibility features?].
  4. Design assets, such as source files for print media, marketing materials, user experience design assets, and any associated metadata, by using authoring tools that support accessible design practice, and validation tools.

Control over content creation

Users, when creating content of any kind, must have complete control over the content they produce while being provided with the guidance and features to make informed decisions about accessibility.

Users may require control over content creation when:

  1. Producing specialized content for educational or diagnostic purposes, such as course or testing materials, where certain parts of content must be inaccessible to fulfill a requirement.
  2. Producing personalized accessible alternatives to other content that prioritizes the accessibility needs of the target user over the needs of other users.
  3. Producing artistic content where creating accessible alternatives may in some way invalidate or harm the intent of the work.

Content modification

The following use cases cover the modification of existing content.

Editing content

Users must be able to edit or modify content in ways that retain existing accessibility features and ensure all content is accessible. When the source content is not accessible, users must be able to remediate the content.

Users may achieve this by:

  1. Using accessible authoring tools that provide the ability to view existing content and its accessibility features.
  2. Using accessible authoring tools that offer the necessary features and guidance to make content accessible.
  3. Using authoring tools that provide the necessary tools to make content accessible.

Adding accessibility metadata to content

Users must be able to add accessibility features and metadata to content when uploading it to its relevant platform.

Users may achieve this by:

  1. Using platforms that provide the ability to add relevant accessibility features or metadata when content is uploaded, such as alternative text, captions, or audio descriptions.
  2. Using platforms that provide features that generate relevant accessibility features or metadata when content is uploaded, such as auto-generation of alternative text or captions.
  3. Using platforms that provide the ability to edit or modify any accessibility information or metadata that is attached to the source or auto-generated by the platform, such as alternative text, captions, or audio descriptions.

Exporting or saving content

Users must be able to save or export content in multiple accessible formats and with any accessibility metadata and features preserved, when content can be developed in multiple formats.

Users may achieve this by:

  1. Using an authoring tool that offers saving or export in multiple formats as a feature.
  2. Using specialized software for the conversion or transformation of content into different formats that preserves accessibility features.
  3. Using software that informs the user of differences or requirements for accessibility that may arise in different formats, such as different metadata values, format constraints, or format-specific features.

Accessibility validation

The following use cases cover the validation or remediation of accessible content.

Checking the accessibility of content

Users must be able to check the accessibility of their content, understand what issues are present, and how to address them.

Users may achieve this by:

  1. Using an authoring tool that has built-in accessibility validation for the content it produces that provides information on the issues and how to address them.
  2. Using an extension or plugin for the authoring tool that provides accessibility validation for the content that provides information on the issues and how to address them.
  3. Using an external tool for validating the accessibility of the content, such as an accessibility monitoring tool, or automated testing tools in production pipelines that provides information on the issues and how to address them.

Repairing accessibility issues in content

Users must be able to repair accessibility issues found in their content.

Users may achieve this by:

  1. Using an authoring tool that provides built-in remediation tools or guidance for repairing issues.
  2. Using an extension or plugin that provides remediation tools or guidance for repairing issues.

Authoring Tool Requirements

The requirements for authoring tools are structured by the actions taken by the user during the authoring process, and what the authoring tool must do to enable them.

Authoring tool accessibility

Authoring tools must be accessible to the user. This requires that:

  1. The authoring tool's interface, features, and documentation must be accessible.
  2. The authoring tool supports use with different assistive technologies.
  3. The authoring tool should offer settings and features that allow users to personalize the interface according to their needs.
  4. The authoring tool must expose all parts of the interface to users, including informative or processing-related content.
  5. The authoring tool must document all of their features.
  6. The authoring tool should support multiple languages and scripts.

Authoring accessible content

Authoring tools must be able to support the creation of accessible content. This requires that:

  1. The authoring tool must follow accessibility best practices when content is automatically generated.
  2. The authoring tool must follow accessibility best practices when content is generated through an interface that reflects the final product not the underlying structure, such as a rich text editor.
  3. The authoring tool must support the addition of accessibility features to the content.
  4. The authoring tool must be able to inform the user of what inputs are required to provide accessible output.
  5. The authoring tool must support the addition of extensions or third-party tools that provide accessibility guidance or features.
  6. The authoring tool must be able to request, store, and associate accessibility metadata to the content.
  7. The authoring tool must support content type-specific accessibility features.

Authoring tool validation

Authoring tools must be able to validate the accessibility of content, and provide the means to repair any issues. This requires that:

  1. The authoring tool has the ability to validate the content against the relevant accessibility best practices for the content.
  2. The authoring tool supports extensions or third-party tools that validate the content against the relevant accessibility best practices for the content.
  3. The authoring tool has the ability to fix accessibility issues automatically or at the direction of the user.
  4. The authoring tool provides the necessary information for the user to address any identified issues.

Authoring tool outputs

Authoring tools must be able to produce outputs that preserve the accessibility features and metadata applied during the authoring process. This requires that:

  1. The authoring tool is able to store and associate accessibility metadata with the content it produces.
  2. The authoring tool ensures that the accessibility features applied during authoring are preserved in the final product(s).
  3. The authoring tool informs the user when an output format requires additional information for accessibility, such as format-specific metadata.
  4. The authoring tool informs the user when an output format has limitations or does not support accessibility features in the source content.
  5. The authoring tool should be able to support multiple languages or scripts, and provide means to translate or transform content into different languages.
  6. The authoring tool should support extensions or tools to provide translation or transformation without any loss of accessibility information if the tool does not support translation or transformation.
